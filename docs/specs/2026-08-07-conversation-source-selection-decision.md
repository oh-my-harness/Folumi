# 会话资料选择与 `@` 功能调整

日期：2026-08-07  
状态：已接受

## 决策

会话输入框不再提供 `@` 指定单篇笔记的功能。用户通过统一的“关联资料”入口，决定整次会话可以参考哪些内容。

“关联资料”采用多选：

- “笔记”和多个资料集可以同时选中；
- 点击一个选项即选中，再次点击即取消；
- 选择面板在点击选项后保持打开，方便连续选择；
- 不显示“不关联资料”选项；当没有任何选项处于选中状态时，自然表示不关联资料；
- 输入框显示已选数量，不使用资料、知识库、RAG 等内部术语解释状态。

## 会话与运行时边界

会话保存选中的资料集 ID 列表和“笔记”开关。服务端逐项验证资料集，并保留每个资料集对应的嵌入模型配置。单个会话最多关联 12 个资料集，避免一次检索无边界扩张。

运行时仍使用标准 Knowledge Source 能力。产品层只负责把当前会话选中的多个资料集组合成一个薄适配器：分别调用已有的 LanceDB 资料源，合并并按相关度排序结果，再由 runtime 完成知识工具编排。Notebook 继续作为独立知识源接入，不与资料集互斥。

## 兼容边界

读取旧会话时仍接受单个 `kb` 字段，并转换为一个元素的资料集列表。新建和更新会话使用 `kbs`。旧的消息级 `@` 候选接口、WebSocket `mentions` 字段及其持久化链路全部移除；历史会话中已保存的相关自定义事件不再展示，也不参与后续回答。

## 验收标准

- 输入框中不再出现 `@` 按钮；
- 关联资料列表中不再出现“不关联资料”；
- 可以选中两个以上资料集，并同时选中“笔记”；
- 再次点击已选项后仅取消该项，不影响其他选择；
- 重开会话后，资料集列表和“笔记”选择均可恢复；
- 检索结果可以来自当前会话选中的任一资料集，未选中的资料集不能被读取。
