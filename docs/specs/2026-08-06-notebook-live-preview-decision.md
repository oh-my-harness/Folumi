# Notebook 正文内直接编辑决策

> 状态：已接受并实现
> 日期：2026-08-06
> 范围：Notebook Markdown 阅读、编辑与保存交互

## 决策

Notebook 使用基于 Milkdown Crepe 的正文内直接编辑作为默认且唯一的正文编辑方式。Markdown 文件仍是持久化事实源，编辑器内部文档模型只负责交互、选区和渲染，不引入第二套产品数据格式。

- 标题、段落、列表、引用、表格、公式和代码块在同一个可编辑文档面中直接操作；
- 不再把正文拆成多个渲染块，也不再用临时 `textarea` 替换被点击的块；
- 光标、跨段选区、撤销/重做、粘贴、快捷键和输入法组合输入统一交给成熟编辑器内核处理；
- 内容变化后短暂防抖并自动保存，编辑器失焦时立即提交尚未保存的内容；
- `Ctrl+S` / `Cmd+S` 仍可立即触发保存，但不再依赖顶部保存按钮；
- 编辑器顶部不再显示“编辑”“保存”“取消”或“删除”操作栏；
- 笔记删除、重命名和目录管理统一由文件树承担；
- 保存仍使用精确 revision，外部修改造成冲突时不得静默覆盖；
- 编辑器初始化、加载和普通选择产生的内部事务不得触发保存；只有观察到用户输入、剪贴、拖放或格式操作后才允许自动保存；
- 保存状态以低干扰文字显示，不创建额外消息或弹窗。

## 技术选型

- 采用 [Milkdown](https://milkdown.dev/) 的开箱即用层 Crepe；Milkdown 基于 ProseMirror 与 Remark，采用 MIT 许可证；
- 使用 Crepe 提供的 CommonMark、GFM、表格、代码块、数学公式、浮动格式工具和拖拽块能力；
- 不直接基于 ProseMirror 自研完整编辑器，也不继续维护自定义 Markdown 分块器；
- 暂不启用 Crepe 的 AI 和图片上传能力。Notebook 的 AI 写入仍通过现有产品链路完成；图片上传需要先确定资源持久化规则，不能保存临时 Blob URL；
- 编辑器可能规范化等价 Markdown（例如列表缩进或空白），产品承诺语义和受支持扩展往返，不承诺每个空白字符原样保存。

## Markdown 兼容边界

第一阶段必须覆盖：

1. CommonMark 与 GFM，包括表格、任务列表和围栏代码块语言；
2. 行内及块级数学公式；
3. `[[目标]]` 与 `[[目标|别名]]` Wiki 链接，不把 `![[资源]]` 误判为笔记；
4. Wiki 链接在编辑态使用 `Ctrl/Cmd + 点击` 打开，普通点击只移动光标；
5. 空笔记、中文输入法、跨段选择、撤销/重做和粘贴；
6. 文件开头的 YAML Front Matter 作为不可见文件元数据从编辑正文中剥离，保存时原样拼回；
7. HTML 注释及其他扩展语法必须通过往返测试后才能声明完整支持；遇到无法无损表达的语法时，应保留源码降级能力，而不是静默删除。

## Markdown 链接规则

- Markdown 标题生成的 `#anchor` 是当前文档内的页内锚点，桌面端不得将其交给系统浏览器；
- Notebook Live Preview 中的标题不显示为可跳转链接，点击标题应进入该标题块的编辑状态；
- `http:`、`https:` 和 `mailto:` 等显式外部链接仍由桌面端外部浏览器打开；
- Wiki 链接和产品来源链接继续使用各自的产品内导航。

## 原因

Notebook 是持续书写空间，不应要求用户在“预览”和“源码输入框”之间切换。旧块级方案虽然尝试模拟 Live Preview，但它破坏了连续光标和跨块编辑，也使输入框边框、尺寸变化和焦点跳转成为主要视觉元素。成熟的单一文档模型更符合直接书写体验，并能显著减少自研编辑器状态代码。

## 回归要求

1. 标题本身可直接放置光标编辑，点击不得打开网页。
2. 正文中不得出现由产品拼装的块级 `textarea`。
3. 用户可以连续选择和修改多个段落，并正常撤销/重做。
4. CommonMark、GFM、公式和 Wiki 链接必须通过 Markdown 往返测试。
5. 自动保存必须串行执行，并继续使用最新 revision；保存冲突不得覆盖外部修改。
6. Wiki 链接普通点击用于编辑，`Ctrl/Cmd + 点击`用于产品内打开或创建笔记。
7. 文件树仍提供删除、重命名和目录操作。

## 被替代方案

同日早期实现的“渲染块 + 点击后显示单块 textarea”方案被本决策替代，不再作为回退路径保留。

## 实现验收

- 自动化测试覆盖 YAML Front Matter 原样拼回、Wiki 链接往返、别名、嵌入链接以及代码区间保护；
- 产品外壳回归测试确认正文编辑器按需加载、没有块级 `textarea`，并且只有观察到真实用户编辑后才允许自动保存；
- 本地端到端验证确认：仅打开笔记不会改写正文；真实编辑后 Front Matter、HTML 注释、表格、公式、Wiki 链接和围栏代码块均能回写；
- 等价 Markdown 允许由编辑器规范化，例如表格分隔行和末尾换行，但产品扩展不得丢失。
