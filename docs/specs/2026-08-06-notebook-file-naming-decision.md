# Notebook 文件命名与重命名决策

> 状态：已接受并实现
> 日期：2026-08-06
> 范围：Notebook 编辑器、文件树与 Notebook API

## 决策

Notebook 中每篇笔记只保留一个用户可管理的名称来源：Markdown 文件名。

- 文件树显示包含扩展名的真实文件名；
- 编辑器顶部不再显示或编辑一份独立的“笔记标题”；
- Markdown 中的一级标题属于正文，不用于决定文件名，也不与文件名自动同步；
- 后端保留的 `title` 字段只是由文件名去掉扩展名后得到的派生值，供搜索、链接和兼容内部数据结构使用；
- 用户通过文件树重命名笔记或目录，可以使用右键菜单，也可以双击名称进行原地编辑；
- 笔记正文更新只修改 Markdown，重命名或移动只修改 Notebook 相对路径；
- Agent 若要重命名笔记，必须使用受约束的移动/路径操作，不得单独写入 `title`。

## 原因

独立标题、文件名和 Markdown 一级标题同时存在时，用户无法判断哪一个才是笔记名称，也容易产生三者不一致。文件名是 Vault 中真实、可移植的标识，因此将其设为唯一命名来源；正文标题继续由用户自由组织。

## 回归要求

1. 新建笔记后，内部 `title` 必须由最终文件名派生。
2. 重命名文件后，磁盘路径、文件树、内部 `title` 和当前打开的详情必须同步更新，Markdown 内容不得改变。
3. 重命名目录后，目录内所有笔记与子目录路径必须同步更新。
4. 文件树必须同时提供右键重命名和双击原地重命名。
5. 编辑器不得重新引入独立标题或路径输入框；如需改变名称或位置，应回到文件树操作。
