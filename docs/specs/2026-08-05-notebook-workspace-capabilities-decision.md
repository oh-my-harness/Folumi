# Notebook 工作区能力保留决策

> 状态：已接受  
> 日期：2026-08-05  
> 适用范围：Folumi 独立“笔记”一级页面

## 背景

旧产品的 Notebook 曾由 Space 页面承载，具备接近编辑器的目录树、Markdown 编辑和笔记关系浏览能力。移除 Space、Quiz、Student Profile 等旧产品概念时，前端将整个 Space 页面替换成了简化的扁平笔记列表。Notebook 后端的目录、Wiki 链接、标签、反向链接、Vault 刷新和文件监听能力仍然存在，但用户无法再从界面正常使用，形成了功能退化。

Notebook 是 Folumi 的独立核心工作区。产品边界收缩不等于把 Notebook 收缩为简单 CRUD 列表。

## 决策

独立 Notebook 页面必须保留以下工作区能力：

1. 左侧为层级文件树，目录优先、名称排序，目录展开状态持久化；大量节点使用虚拟滚动。
2. 支持从根目录或指定目录新建笔记和子目录。新建目录使用文件树内联命名，不调用浏览器或系统原生输入弹窗；Enter 或失焦确认，Esc 取消。桌面目录右键菜单提供目录内新建、复制路径和删除目录，不重复提供已有左键箭头承担的展开/折叠操作；文件树空白区域的右键菜单必须提供根目录新建笔记、新建目录和刷新 Vault。目录删除仅允许空目录，前后端都不得把它实现为静默递归删除，以免误删笔记或外部 Vault 中未被 Notebook 索引的文件。
3. 中间为 Markdown 编辑与渲染预览区；标题和路径可编辑，保存使用 revision 冲突检查。
4. 右侧为可折叠的关系面板，展示标签、出链、未解析 Wiki 链接、反向链接和局部关系图。
5. 已解析 Wiki 链接在 Notebook 内导航；未解析链接可以直接创建对应笔记。
6. 页面显示 Vault 文件监听状态，并提供手动刷新入口；删除仍需确认并提供本次运行内的撤销恢复入口。
7. Notebook 继续作为独立一级页面，不重新引入 Space、Quiz、Student Profile 或旧记忆文件管理。
8. “新建笔记”和“新建目录”属于同级资源管理操作，顶部并列按钮使用一致的视觉层级，不用颜色制造不存在的主次关系。

## 数据与实现边界

- 页面继续复用现有 `/api/notebook/*` 契约，不在前端维护平行笔记索引。
- 用户拥有的 Markdown 文件与 Vault 是权威数据；树、标签和链接关系来自 Notebook store 的索引与解析结果。
- Knowledge Base 只保存 RAG Sources，不承载可编辑笔记。
- Assistant 读取和修改笔记仍通过受限 Notebook 工具和 revision/路径约束完成。

## 防退化要求

- PRD 的 Notes 章节与用户手册必须同步描述上述能力。
- 产品外壳测试必须检查文件树、关系面板、Wiki 链接、目录 API、桌面上下文菜单和 Vault 状态仍在独立 Notebook 页面中。
- 后续若要改为扁平列表、移除关系面板或将 Notebook 合并到其他一级页面，需要新的明确产品决策，并同步修改 PRD、用户文档和回归测试。
